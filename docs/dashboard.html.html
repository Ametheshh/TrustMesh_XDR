F · Privacy / Limitations

Implemented experiments and their limits

Measured / implementedBehavior demonstrated by the controlled code path; not a general privacy guarantee.

Local-data boundary

In the networked localhost POC, client records stay in the client process; model arrays, training-example counts, and scalar evaluation summaries are communicated. This is a same-machine simulation.

Update clipping / noise

Client-update L2 clipping and seeded Gaussian noise are implemented as an experimental mode. The noise experiment is DP-inspired.

Pairwise masking

A deterministic two-client masking experiment is implemented; masks are constructed to cancel under example-count-weighted FedAvg.

Research POC

DP-inspired clipping + Gaussian noise

This is an experimental mechanism only. No privacy accountant or formal epsilon-DP guarantee is implemented.

Secure-aggregation masking

This is a masking proof of concept, not cryptographic secure aggregation. It provides no cryptographic security guarantee.

Limitations

No formal privacy guarantee

No formal epsilon-DP guarantee and no cryptographic secure-aggregation guarantee.

Simulated clients

Clients are dataset-derived simulations, not real organizations.

No live telemetry or alerts

This is a static dashboard only; there is no live telemetry, operational TAXII service, or alerting.

Performance limitation: federated performance is not uniformly better across clients. Milestone 5's UNSW global model predicted all evaluation rows benign; the Milestone 7 shared-normalization ablation improved but did not close the gap to the UNSW local model.
